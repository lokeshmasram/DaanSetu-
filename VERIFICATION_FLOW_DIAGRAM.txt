╔══════════════════════════════════════════════════════════════════════════════╗
║                         REDUNDANCY & RELIABILITY                             ║
╚══════════════════════════════════════════════════════════════════════════════╝

The system uses TWO methods to ensure reliability:

┌────────────────────────────────┐  ┌────────────────────────────────┐
│  PRIMARY: Socket.IO            │  │  BACKUP: API Polling           │
├────────────────────────────────┤  ├────────────────────────────────┤
│ • Instant notification         │  │ • Checks every 30 seconds      │
│ • Real-time update             │  │ • Works if Socket.IO fails     │
│ • No page refresh needed       │  │ • Catches missed events        │
│ • Best user experience         │  │ • Reliable fallback            │
└────────────────────────────────┘  └────────────────────────────────┘

If Socket.IO fails → API polling catches it within 30 seconds
If API fails → Socket.IO provides instant update
Both fail → User can manually refresh page
